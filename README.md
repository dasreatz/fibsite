## Оновлення дизайну — 23 листопада 2026 року

**Підрозділи:** чотири фото-картки розміщено в одному горизонтальному ряду на комп’ютерах, із м’якою золотистою рамкою лише при наведенні. На вузьких екранах сітка адаптується. Напис «Переглянути підрозділ» не показується.

**Ліміт GitHub:** в архіві лише вихідні файли. Згенеровану папку `dist/` не завантажуйте у GitHub: Render відновлює її через `npm run build`, а GitHub Actions так само збирає сайт. Це зменшує кількість файлів до рівня нижче ліміту 100.


- Підрозділи: прибрано публічні параметри відбору з окремих сторінок; розширено опис; окрема галерея з двох компактних фото; лаконічні поля «Керівник» і «Заступник». Для ДКБ повернуто тематичний кадр кіберцентру із наявних матеріалів проєкту.
- Керівництво: вертикальне дерево з видимими з’єднувальними лініями, видовжені картки; емблема використовується як тимчасове зображення, доки не надано портретів; лише ім'я і посада, натискання відкриває досьє.
- Академія: послідовність із шести етапів з нумерацією 01–06 без дублювання номерів; мінімальні ранги зібрано тут, в окремому блоці профільних напрямів.
- Новини й документи: компактні тематичні символи по центру, без рамок та надлишкових посилань; публічні нормативні посилання в документах залишено.
- Контакти: компактні кнопки з логотипами. Discord, пресслужба, законодавство і вступ мають робочі посилання; Instagram і TikTok не ведуть на вигадані акаунти до публікації реальних адрес.
- Верхні фони вкладок уніфіковані, а фон при наведенні працює й для поточної вкладки. Темний блок «Про бюро» та рухлива емблема збережені, без накладання один на одного.
- Сторінку вступу та її функціональність заявок не переробляли.

## Структура проєкту

```text
fibsite-main/
├── .github/workflows/pages.yml   # Автоматична публікація на GitHub Pages
├── app/
│   ├── layout.mjs                 # Головна, спільна шапка/підвал, HTML-сторінки
│   ├── home-i18n.mjs              # Переклади головної сторінки
│   ├── interior.mjs               # Внутрішні сторінки
│   └── content.mjs                # Дані підрозділів, посилання, контент
├── assets/
│   ├── flags/                     # Прапори перемикача мов
│   └── units/                     # Зображення підрозділів
├── lib/recruitment.mjs            # API для заявок і приватного кабінету
├── tests/                         # Автоматичні перевірки
├── app.js                         # Інтерактивність у браузері
├── styles.css                     # Стилі сайту, включно з рамкою на головній
├── build.mjs                      # Збирання статичного сайту
├── server.mjs                     # Вебсервер із серверним API
├── package.json                   # Команди запуску
├── .env.example                   # Приклад змінних середовища, БЕЗ паролів
└── dist/                          # ЄДИНА згенерована версія сайту
```

`dist/` створюється автоматично, не редагуйте її вручну. У проєкті більше немає старих паралельних реалізацій `src/`, `public/`, `scripts/`, зайвої сторінки `activity/`, дублікатів HTML у корені чи невикористаних зображень. Кожна сторінка підключає спільні `styles.css`, `app.js` та зображення, а не дублює їх у HTML.

## Запуск і перевірка

Потрібен **Node.js 22**; встановлювати пакети не потрібно.

```bash
npm run build
npm test
npm start
```

Відкрийте **http://localhost:3000/**. Для локального перегляду можна залишити приймання заявок вимкненим. Не відкривайте `dist/index.html` подвійним кліком: сайт використовує маршрути та абсолютні шляхи; потрібен сервер.

Для інших портів задайте змінну середовища `PORT`. Щоб змінити вміст рамки на головній, відкрийте `app/layout.mjs` і знайдіть `home-bureau-frame`; її стилі — наприкінці `styles.css`, а переклади — у `app/home-i18n.mjs`.

## Публікація

**GitHub Pages:** завантажте вихідні файли в репозиторій GitHub (папку `dist/` можна не завантажувати). У Settings → Pages → Build and deployment виберіть **GitHub Actions**. Workflow `.github/workflows/pages.yml` перевірить і збере сайт із правильним префіксом адреси репозиторію, потім опублікує `dist/`. Старий режим публікації **з кореня гілки** для цієї очищеної структури більше не використовується.

**Інший статичний хостинг:** виконайте `npm run build` і публікуйте **вміст** папки `dist/` за кореневою адресою домену. Якщо сайт розміщується в підпапці, задайте `SITE_BASE_PATH=/назва-папки/` перед запуском збірки.

**Сервер з анкетами:** `npm start` запускає `server.mjs`, який віддає `dist/` і окремо обслуговує `/api/*`. GitHub Pages є лише статичним хостингом, тому заявки там будуть чесно позначені як недоступні; вони не відправлятимуться й не зберігатимуться без бекенда.

## Захист заявок

Для запуску приймання заявок на Node-хостингу задайте **через налаштування хостингу** змінні `FIB_APPLICATIONS_OPEN=true`, `FIB_ADMIN_PASSWORD` (мінімум 12 символів), `FIB_SESSION_SECRET` (мінімум 32 символи), `FIB_DATA_DIR` (приватна постійна директорія поза `dist/`). Звичайний `npm start` не завантажує `.env` автоматично. Файли з персональними заявками та секрети ніколи не мають потрапляти до `dist/` або GitHub.

Усі 14 сторінок доступні трьома мовами (42 локалізовані маршрути). Перед публікацією запускайте `npm test`.
