# FIB Olymp — інтегрований пакет

## Почніть з `RENDER_DEPLOY.md`

Збережено вихідний публічний сайт із `fibsite-main(2).zip` (42 локалізовані сторінки). Додано посилання «Кабінет», поля email та добровільного Telegram у заявці, реєстрацію за запрошенням. `server.mjs` обслуговує єдиний сайт і серверний API. `/staff/` переводить у `/cabinet/`.

### Що реально реалізовано в серверному контурі
- Вступ: приватна заявка → рішення рангів 10–12 → HTML-лист рішення через Resend → персональне запрошення на 72 години → реєстрація Supabase Auth → Intern, без підрозділу, доступ до Академії. Статус доступний за номером та секретним кодом. Запрошення не показується в публічному статусі, а надсилається на email.
- Telegram: добровільне підключення через одноразове deep link та webhook із секретом. Бот надсилає лише загальні сповіщення про рішення. `/stop` вимикає сповіщення.
- Авторизація: сервер перевіряє Supabase access token та активність облікового запису; cookie HttpOnly, SameSite Strict, Secure на HTTPS. Сесія до 1 години, повторний вхід після закінчення; поки без refresh та самостійного відновлення пароля.
- Кабінет: головна, профіль, Академія (3 стартові уроки та автоматичний прогрес), особовий склад, заявки. Ранги 7–9 бачать реєстр власного підрозділу, 10–12 — загальний. Лише Director змінює звання/підрозділ/посаду/активність. Ранг і активність перевіряються на сервері, таблиці Supabase недоступні anon/authenticated напряму.
- Лист рішення має службовий стиль, номер заявки, дату, підставу відмови, дані підписанта. Позначено, що це документ ігрової спільноти, не державного органу. Це HTML-лист, не PDF-вкладення.

### Межі поточної інтеграції (важливо)
`offline/FIB_Olymp.html` — повний старий локальний інтерфейс з виправленими кадровими бланками. Він **не** є серверним кабінетом, не публікується через build, не синхронізує записи з Supabase. Документообіг, слідчий реєстр, досьє, завдання, оголошення, календар, розширена Академія, кадрові рішення, права з перемикачами, посвідчення та ШІ ще не перенесені у багатокористувацький серверний режим. Не публікуйте цей HTML як багатокористувацький кабінет. Дані GTA-персонажів не повинні містити реальних персональних даних інших людей.

Ключі, база, пошта та бот не підключені до ваших реальних акаунтів автоматично. Схема SQL та REST-контракт перевірені на рівні коду та тестових відповідей, не виконувалися в живому Supabase. Доставку email/Telegram і роботу на Render треба перевірити після налаштування. Email-статус `accepted` означає прийняття сервісом, не підтверджену доставку. Повторне запрошення анулює попереднє, не відновлює вже використане.

Перед широким запуском потрібні резервні копії, парольне відновлення/MFA, перевірка RLS, політика зберігання та видалення заявок, пагінація (поточний ліміт 500), стійка черга повідомлень, антиспам і обробка збоїв реєстрації. У разі збою між створенням Auth user та записом member система пробує видалити створений user і відновити заявку; якщо збій не дозволив відкотити операцію, заявка може лишитися `registering`, яку має перевірити адміністратор перед повторною спробою. Аудит базовий, не незмінний. Власник проєкту відповідальний за зберігання мінімуму даних та дотримання правил сервісів.

### Структура
- `app/`, `assets/`, `app.js`, `styles.css` — публічний сайт.
- `cabinet/` — серверний кабінет (інтерфейс).
- `lib/portal.mjs` — серверні API, Auth, Resend, Telegram.
- `supabase/001_portal.sql` — таблиці, обмеження та RLS.
- `supabase/002_director.example.sql` — прив'язка першого Director до UUID Auth.
- `.env.example` — назви змінних, без ключів.
- `tools/telegram-webhook.mjs` — реєстрація webhook.
- `offline/` — окремий локальний кабінет, не публікується.
- `tests/` — перевірки публічного сайту, старого API (залишено для сумісності тестів), нового серверного контуру з mock-сервісами.

`npm run build && npm test` — 41 тест. `npm start` — локальний перегляд. Для локальної роботи з ключами Node 22: `node --env-file=.env server.mjs`. Без конфігурації заявки вимкнені. `lib/recruitment.mjs` лишився для старих тестів; новий server.mjs його не використовує. Автоматичного перенесення старих заявок або localStorage немає.
